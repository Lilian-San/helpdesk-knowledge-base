## What is Root Cause Analysis?

It is a structured process for identifying the fundamental reasons behind IT incidents and problems, aiming to implement permanent solutions and prevent them from reoccurring. 

## Why is it important?

It helps IT support to have a more strageic approach rather than reactive. It can improved resilience, reduce risk and align better with business goals.

### Common Techniques

- **The 5 whys:** This technique places an emphasis on asking why to delve deep enough into the problem that the solution becomes clear. 
- **Fishbone Diagram:** This technique focuses on identifying and categorsing potential causes of a problem.
- **Timeline Analysis:** This technique involves reconstructing the sequence of events leading up to an incident, helping to identify where the issue originates.
## Example (5 Why's):

**Problem:** File transfers are slow.

**Why?**

- Because network performance is poor.

**Why?**

- Because connection speed is reduced.

**Why?**

- Because packets are being lost.

**Why?**

- Because the network cable is damaged.

**Why?**

- Because the cable was bent and worn over time.

**Root Cause:** Damaged network cable.
